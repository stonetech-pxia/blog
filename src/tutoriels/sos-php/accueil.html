FaillesCVE-2026-109618 et CVE-2026-109619 (« PHP2Shell »)
GravitéCritique – 9,2 / 10 (CVSS v4.0)
ConséquenceExécution de code à distance sans authentification, quelle que soit l'application
Versions vulnérablesToutes les versions antérieures aux versions corrigées ci-dessous, y compris les anciennes (5.x, 7.x, 8.0, 8.1)
Versions corrigées8.2.35 · 8.3.36 · 8.4.27 · 8.5.12 (ou plus récentes)
PHP 8.1 et plus ancienPlus maintenu : seuls des correctifs « source » existent pour 7.4, 8.0 et 8.1. Il faut migrer vers 8.2 minimum ou passer par un fournisseur de support étendu.
SolutionLa mise à jour est la seule protection complète. Les réglages de contournement ne protègent que partiellement.

Pourquoi c'est grave, expliqué simplement

Imaginez que votre site soit une boutique. Ces failles ne permettent pas seulement de casser une vitrine : elles donnent au cambrioleur les clés de l'arrière-boutique. Un pirate peut alors voler les données de vos clients, installer un virus, envoyer des spams depuis votre serveur ou effacer votre site.

Il n'a besoin ni de mot de passe ni d'une erreur de votre part : il suffit que votre serveur utilise une version de PHP non corrigée. C'est pour cela que de nombreux sites se sont mis en maintenance le temps de se mettre à jour.

Méfiez-vous des faux outils. De faux programmes de « test de vulnérabilité » circulent déjà sur GitHub et contiennent du code malveillant. N'exécutez jamais un script que vous ne comprenez pas ou dont vous ne connaissez pas l'origine. Ce guide ne vous demandera jamais de télécharger ou d'exécuter un script : nos guides n'utilisent que des commandes standard, expliquées une par une, et les outils de votre hébergeur.
